### Local storage isolation incident and recovery

The earlier test harness isolated ports but did not isolate the Storage emulator's temporary directory. Firebase Tools 15.34.2 uses `os.tmpdir()/firebase/storage/blobs` and deletes that entire directory on shutdown. A test shutdown could therefore delete blobs belonging to a concurrently running development suite. During this follow-up the development Node services stopped when accessing missing objects; the surviving Firestore metadata was backed up under ignored `.firebase/workspace-recovery`. This was an implementation defect, not an IAM/rules or AI_BASE_URL issue.
